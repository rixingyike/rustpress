# 2 目录的规定

docs layout 改为 doc layout，doc 代替结构化渲染。
docs layout 代表电子书列表页面。


准备让目录有专用。特定的目录干特定的用途。


assets：图片，不用扫描
projects：项目目录，里面的 md 都是 project layout
docs：结构化文档，子目录是电子书，子目录下有 layout 等于 doc 的 index.md，这样的子目录要作为 mdbook 做结构化渲染
blog：博客目录，一般子目录是年名，例如 2025、2026，也可以是其它名字，子目录就是分类名称。每个子目录下的 md 文件，就是该分类的博客文章。引外，由于历史原因，posts 目录与 blog 等同看待，但建议以后不再使用 posts 目录。

# 5

要引入一个类库，负责解析md 文件

负责 Frontmatter：gray-matter
地位： 解析 Frontmatter 的“事实标准”。只要你的 Markdown 顶部有 --- 包裹的 YAML，交给它准没错。

关于“拓展性”： gray-matter 天生就是无边界拓展的！它底层调用的是 YAML 解析器，把你写的所有字段直接转换成一个 JavaScript 对象（JSON）。你随便加什么字段（比如 music: "xxx", weather: "sunny"），它都能原封不动地解析出来。

用法示例：

TypeScript
import matter from 'gray-matter';

const fileContent = `---\ntitle: 我的文章\ntags: [Tauri, Vue]\ncustomField: 任意拓展内容\n---\n# 一级标题\n正文内容`;
const parsed = matter(fileContent);

console.log(parsed.data); // { title: '我的文章', tags: ['Tauri', 'Vue'], customField: '任意拓展内容' }
console.log(parsed.content); // "# 一级标题\n正文内容" (纯净的正文，已经剔除了头部)
