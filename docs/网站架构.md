# 网站导航与编译架构设计

本文记录关于 RustPress 静态博客系统的导航架构设计理念，解决“什么时候编译成单页面（如 `.html`），什么时候编译成子目录（如 `/index.html`）”的核心问题，并对整站 URL 进行了规范。

---

## 一、 编译形态决策：单页面 (Single Page) vs 子目录 (Sub-directory)

在静态网站生成器中，对于不同的内容列表或页面，我们在输出时有两种编译策略：
1. **单页面文件**：生成为 `/parent/tags/{{ tag }}.html`。
2. **子目录索引**：生成为 `/parent/tags/{{ tag }}/index.html`。

### 1. 决策维度：内容创作总量 (Content Volumetric Scale)

我们如何决定使用哪种策略？其核心决定性因素是 **“内容的预计增长上限”** 与 **“是否需要分页（Pagination）”**。

* **使用【单页面文件】的场景：**
  * **特征**：内容有天然的上限，即便是高产的作者，一生中创作该分类内容的数量也是有限的（通常在几十到一百以内），且内容无需分页展示。
  * **典型例子**：专栏标签页面（如 `/columns/tags/前端.html`）、著作/作品首页（如 `/works.html`）、项目展示页（如 `/projects.html`）、关于我页面（如 `/about.html`）、友链页面（如 `/friends.html`）。
  * **优势**：URL 结构扁平，避免了不必要的嵌套子目录；文件结构简洁，编译生成更迅速。

* **使用【子目录索引】的场景：**
  * **特征**：内容理论上可以无限增长（如日记、技术博客文章、碎片闲言等），必须提供多页分页支持（如 `index.html`、`index1.html`、`index2.html`）。
  * **典型例子**：博客首页列表、博客文章分类（如 `/categories/rust/index.html`）、博客文章标签（如 `/tags/rust/index.html`）、碎碎念闲言（如 `/tweets/2026/07/index.html`）。
  * **优势**：分页文件可以平铺在相同的子目录下（如 `index.html` 与 `index1.html` 同级），URL 的目录层次清晰，利于 SEO 和面包屑导航的语义解析。

### 2. 列表分页补充规则

针对系统中的各类列表页面：
* **数据量大、需要分页的列表**：必须编译至子目录下，并使用 `index.html` 作为文件名（伴随 `index1.html`、`index2.html` 等分页页面平铺在该子目录中）。
* **数据量小、无分页需求的列表**：直接编译为单页面文件（如 `/columns/tags/{{ tag }}.html`），无需为每个子项创建独立的物理文件夹，保持磁盘结构清爽，精简 URL 层级。

## 二、 现状排查与整站导航优化方案

当前 RustPress 存在菜单与物理生成路径的不对称问题，导致在本地开发服务器预览或部分静态托管平台上，点击菜单链接会因为 `.html` 后缀未生成而退回首页或报 404。

### 1. 现状不一致点分析

| 栏目 | 配置文件中菜单 URL | 物理生成路径 | 实际访问状态 |
| --- | --- | --- | --- |
| **归档** | `/archives/` | `archives/index.html` | ✅ 正常访问 |
| **分类** | `/categories.html` | `categories/index.html` | ❌ 404/Soft-404 退回首页 |
| **标签** | `/tags.html` | `tags.html` 与 `tags/index.html` | ✅ 正常访问（双写兼容） |
| **友链** | `/friends.html` | `friends.html` | ✅ 正常访问 |
| **项目** | `/projects.html` | `projects/index.html` | ❌ 404/Soft-404 退回首页 |
| **关于** | `/about.html` | `about.html` | ✅ 正常访问 |

### 2. 优化方向：规范化现代 URL（Modern URLs）

为彻底解决文件路径不对称造成的 404 隐患，建议将全站的**系统性栏目列表**和**单页面**统一规范为**以 `/` 结尾的目录结构**：

1. **统一使用无后缀目录**：将配置文件中的主菜单和模板内的跳转全部改为 `/categories/`、`/tags/`、`/projects/`、`/friends/`；而对于关于我页面，直接保留为 `/about.html` 单页面。
2. **规范物理输出**：
   * 标签列表页只生成至 `tags/index.html`。
   * 分类列表页只生成至 `categories/index.html`．
   * 友链页面（因包含分页）在 `generator.rs` 中改为写入 `friends/index.html`。
3. **保持单页面化的场景**：
   * 作者简介页 `/about.html` 与专栏标签页等，因均符合“内容唯一、无分页”的原则，因此继续保持在各自的 `.html` 单页面形态，无需创建多余目录，保持简洁。
