这是一份提供给 AI Agent 用于实现纯静态无数据库专栏支付系统的详细技术说明书。请根据以下说明逐一实现对应的核心模块。

系统架构总览
本系统采用双码分离架构，以实现零数据库的静态页面付费解锁。内容密钥用于在静态网站编译阶段加密文章内容。购买凭证是一个采用 JWT 格式的字符串，在用户支付成功后下发。前端使用购买凭证向服务器动态换取内容密钥，从而在本地完成页面解密。

全局配置与环境变量
Serverless 后端服务需要配置以下环境变量。第一组是 PAYPAL_CLIENT_ID 和 PAYPAL_SECRET，用于向 PayPal 官方接口校验订单状态。第二组是 JWT_SECRET，作为签发和校验购买凭证的唯一私钥，必须高强度保密。第三组是 RESEND_API_KEY，用于调用邮件发送服务。第四组是 DOC_KEYS，它是一个 JSON 映射表，记录了当前每个专栏 ID 对应的内容密钥，例如记录了专栏 A 对应密钥为 Key_123。

模块一：静态博客编译端加密逻辑
在静态博客生成器将 Markdown 转换为 HTML 的过程中，需拦截解析过程。系统读取 Markdown 文件的头部元数据，若识别到 is_free 字段为 false，则提取该文章的 doc_id。随后，程序通过环境变量获取该 doc_id 对应的当前内容密钥。使用 AES-256-GCM 算法对转换后的 HTML 核心内容进行加密。输出的最终静态 HTML 文件中，不可包含明文内容，必须以特定的 HTML 标签包裹加密后生成的 Base64 密文、初始化向量 IV 以及认证标签 Auth Tag，同时将 doc_id 附着在容器的自定义属性上。

模块二：前端支付与验单发起
在加密文章的页面底部，前端需要加载 PayPal JS SDK 并渲染支付按钮。当用户点击购买时，前端需要提供一个输入框让用户填写接收凭证的电子邮箱。PayPal 支付流程在客户端弹窗内完成，支付成功后，onApprove 回调函数会接收到 PayPal 返回的 orderID。此时，前端需立即构造一个 HTTP POST 请求，发送至 Serverless 后端的验单接口，请求体中必须包含 orderID、用户邮箱以及当前文章所属的 doc_id。

模块三：后端验单与凭证下发接口
Serverless 验单接口接收到前端的请求后，首先使用环境变量中的 PayPal 密钥，直接向 PayPal 服务器发起查单请求，确认该 orderID 真实存在且状态为已付款。验证通过后，后端使用 JWT_SECRET 签发一个 JWT 字符串作为购买凭证。该 JWT 的载荷中必须包含用户的邮箱和授权阅读的 doc_id，且不设置过期时间。最后，后端调用 Resend 邮件接口，将这段 JWT 字符串发送至用户的邮箱，并返回成功状态给前端，提示用户查收邮件。

模块四：前端解锁与自动续钥逻辑
当用户访问被锁定的文章时，前端脚本优先检查浏览器的 localStorage 中是否存在对应 doc_id 的 JWT 购买凭证。若不存在，则展示要求输入凭证的界面供用户手动填写。一旦获取到 JWT，前端会向 Serverless 后端的换钥接口发送 HTTP POST 请求，获取当前的内容密钥。前端利用 Web Crypto API，结合获取到的内容密钥，对页面中的密文、IV 和 Auth Tag 进行 AES-256-GCM 解密。若解密成功，将密文替换为明文 DOM，并将验证有效的 JWT 存入 localStorage 以备后用。若 Web Crypto API 抛出解密失败的异常，说明后端更换了内容密钥。此时前端通过 catch 捕获异常，利用 localStorage 中长期有效的 JWT 再次向换钥接口请求最新的内容密钥，随后重新执行解密流程，实现用户无感知的密钥轮换。

模块五：后端换钥接口
Serverless 换钥接口专门用于处理前端的解密请求。它接收前端传来的 JWT 字符串，首先使用 JWT_SECRET 进行签名合法性校验，防止伪造。校验通过后，解析出载荷中的 doc_id，随后在 DOC_KEYS 环境变量中查找该 doc_id 当前配置的内容密钥。后端将该内容密钥以纯文本或 JSON 格式返回给前端。

下面提供一段基于 Web Crypto API 的前端解密核心参考代码，用于指导前端解密模块的实现。

```javascript
async function decryptContent(encryptedBase64, ivBase64, tagBase64, keyBase64) {
    const keyBuffer = Uint8Array.from(atob(keyBase64), c => c.charCodeAt(0));
    const cryptoKey = await crypto.subtle.importKey(
        "raw",
        keyBuffer,
        { name: "AES-GCM" },
        false,
        ["decrypt"]
    );
    
    const ciphertextBuffer = Uint8Array.from(atob(encryptedBase64), c => c.charCodeAt(0));
    const ivBuffer = Uint8Array.from(atob(ivBase64), c => c.charCodeAt(0));
    const tagBuffer = Uint8Array.from(atob(tagBase64), c => c.charCodeAt(0));
    
    const dataWithTag = new Uint8Array(ciphertextBuffer.length + tagBuffer.length);
    dataWithTag.set(ciphertextBuffer, 0);
    dataWithTag.set(tagBuffer, ciphertextBuffer.length);

    try {
        const decrypted = await crypto.subtle.decrypt(
            { name: "AES-GCM", iv: ivBuffer },
            cryptoKey,
            dataWithTag
        );
        return new TextDecoder().decode(decrypted);
    } catch (error) {
        throw new Error("解密失败，密钥可能已轮换");
    }
}

```
