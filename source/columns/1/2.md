# FFI 与 C 语言互操作

这是专栏《Rust 高级编程与异构系统》的第 2 篇文章。

## 学习目标

- 理解 Rust FFI 的核心机制与调用约定。
- 掌握 `extern` 块的使用及 C 数据布局。

## extern 块与 C ABI

Rust 通过 `extern "C"` 声明遵循 C ABI 的函数接口，使得跨语言调用变得可能。C ABI 是操作系统层面的标准调用约定，所有主流语言都支持与之互操作。

```rust
extern "C" {
    fn malloc(size: usize) -> *mut std::ffi::c_void;
    fn free(ptr: *mut std::ffi::c_void);
}

unsafe {
    let ptr = malloc(1024);
    // 使用内存...
    free(ptr);
}
```

## #[repr(C)] 与内存布局

Rust 结构体的默认内存布局是未定义的，编译器可以自由优化字段顺序。但通过 `#[repr(C)]` 可以强制使用 C 风格布局，保证字段顺序与 C 结构体一致：

```rust
#[repr(C)]
struct Point {
    x: f64,
    y: f64,
}

#[repr(C, packed)]
struct Packed {
    a: u8,
    b: u32,  // 无对齐填充
}
```

## 字符串双向传递

在 Rust 与 C 之间传递字符串需要处理所有权和编码问题。C 字符串以空字符 `\0` 结尾，而 Rust 字符串是长度前缀的 UTF-8：

```rust
use std::ffi::{CString, CStr};

fn to_c_string(s: &str) -> CString {
    CString::new(s).expect("CString 不能包含空字符")
}

fn from_c_str(ptr: *const i8) -> &'static str {
    unsafe { CStr::from_ptr(ptr).to_str().unwrap() }
}
```

## 使用 bindgen 自动生成绑定

对于大型 C 库，手动编写 FFI 绑定既繁琐又容易出错。`bindgen` 工具可以自动从 C 头文件生成 Rust FFI 绑定：

```bash
bindgen include/foo.h -o src/bindings.rs
```

生成的绑定会包含 `extern` 块、类型定义和常量，大大减少了手动工作量。

## 安全封装模式

与 unsafe 代码一样，FFI 调用应当封装在安全的 Rust 函数中。将不安全的 C API 转化为安全的 Rust 接口，是 Rust FFI 的最佳实践。`libc` 和 `winapi` 等 crate 都是这种模式的典范。
