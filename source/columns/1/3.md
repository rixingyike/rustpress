# 异步运行时的生命周期与 Pin

这是专栏《Rust 高级编程与异构系统》的第 3 篇文章。

## 学习目标

- 理解 Future trait 的执行模型与 Pin 的作用。
- 掌握异步运行时中任务的生命周期管理。

## Future 的执行模型

Rust 的异步编程基于 `Future` trait：一个 `Future` 代表一个可能尚未完成的值。当调用 `poll` 时，如果任务就绪则返回 `Poll::Ready(value)`，否则返回 `Poll::Pending`。

```rust
use std::task::{Context, Poll};
use std::pin::Pin;

trait SimpleFuture {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}
```

## Pin 的核心作用

`Pin` 解决了异步 Rust 中一个关键问题：自引用结构体。当一个 `Future` 中包含指向自身字段的指针时，移动该结构体会导致悬垂指针。`Pin` 确保数据在内存中的位置不会移动：

```rust
use std::pin::Pin;
use std::marker::PhantomPinned;

struct SelfReferential {
    data: i32,
    ptr: *const i32,
    _pin: PhantomPinned,
}
```

`Pin<Box<T>>` 和 `Pin<&mut T>` 是两种最常见的 pinned 指针形式。

## 异步运行时的任务调度

Tokio 和 async-std 等运行时使用工作窃取调度器来管理异步任务。每个任务在被生成时会注册到运行时的事件循环中，当任务 `await` 某个 I/O 操作时，运行时会将其挂起并调度其他任务执行。

```rust
#[tokio::main]
async fn main() {
    let handle = tokio::spawn(async {
        // 异步任务
        42
    });
    let result = handle.await.unwrap();
}
```
