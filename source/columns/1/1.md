# 深入理解不安全 Rust

这是专栏《Rust 高级编程与异构系统》的第 1 篇文章。

## 学习目标

- 理解 unsafe Rust 的设计哲学与使用场景。
- 掌握裸指针、`unsafe` 块与外部 FFI 的交互。

## 什么是 unsafe Rust

`unsafe` 是 Rust 中一块特殊的能力区域。当你使用 `unsafe` 关键字时，你告诉编译器："我知道这段代码有一些编译器无法验证的安全性保证，但我自己会保证它不会出问题。" 这并不意味着代码不安全，而是说安全性需要程序员来维护。

```rust
unsafe {
    // 在这里你可以做的事情：
    // - 解引用裸指针
    // - 调用 unsafe 函数
    // - 访问或修改可变静态变量
    // - 实现 unsafe trait
}
```

## 裸指针操作

裸指针 `*const T` 和 `*mut T` 是 C 语言指针的 Rust 版本。与引用不同，裸指针可以绕过借用检查器：

```rust
let mut x = 42;
let ptr: *mut i32 = &mut x;
unsafe {
    *ptr = 100;
}
assert_eq!(x, 100);
```

裸指针的主要应用场景包括与 C 语言互操作、手动管理内存布局，以及在某些数据结构中实现内部可变性。

## 外部函数接口 (FFI)

通过 `extern` 块，Rust 可以调用 C 库中的函数：

```rust
extern "C" {
    fn puts(s: *const i8) -> i32;
}

unsafe {
    let msg = "Hello from Rust FFI\0";
    puts(msg.as_ptr() as *const i8);
}
```

这种方式在调用操作系统 API 或嵌入现有 C 代码库时非常有用。

## 安全抽象的原则

编写 unsafe 代码时，一个核心原则是尽量将其封装在安全的抽象背后。对外暴露的 API 应当是安全的，而 unsafe 逻辑只存在于内部实现层。这种模式在标准库中随处可见——例如 `Vec::get_unchecked` 是 unsafe 的，但 `Vec::get` 在内部使用它时做了边界检查，对外呈现为安全的接口。

## 使用 Miri 验证 unsafe 代码

Miri 是 Rust 官方的 undefined behavior 检测工具。通过 `cargo +nightly miri run` 可以检查代码中是否存在未定义行为：

```bash
cargo +nightly miri test
```

它能够捕获内存泄漏、越界访问、对齐错误等问题，是编写安全 unsafe 代码的重要辅助工具。
