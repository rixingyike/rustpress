# 编译优化与二进制体积缩减

这是专栏《Rust 高级编程与异构系统》的第 6 篇文章。

## 学习目标

- 理解 LTO、panic=abort 和 codegen-units 对二进制体积的影响。
- 掌握常用的 Release 优化配置。

## LTO（链接时优化）

LTO 允许链接器在跨 crate 边界执行优化，包括内联和死代码消除。在 `Cargo.toml` 中启用：

```toml
[profile.release]
lto = true
```

`lto = "thin"` 是更快的折中方案，适合大型项目。LTO 可显著减小二进制体积，但会增加链接时间。

## panic=abort 策略

默认情况下 Rust 的 panic 会展开栈帧，这需要在二进制中包含栈展开元数据。将 panic 策略改为 abort 可以消除这些元数据：

```toml
[profile.release]
panic = "abort"
```

这一项改变通常可以减少 10-30% 的二进制体积，代价是 panic 时无法获得完整栈回溯。

## codegen-units 优化

Rust 编译器默认使用 16 个 codegen 单元进行并行编译。但这会阻止某些跨单元优化。减少 codegen 单元可以让编译器做更多优化：

```toml
[profile.release]
codegen-units = 1
```

将 codegen-units 设为 1 会最大化优化机会，但会显著增加编译时间。

## 使用 strip 移除符号

发布构建时移除调试符号可以大幅减小体积：

```toml
[profile.release]
strip = true
```

这对于最终发布二进制尤为重要，调试信息可能占据文件体积的 30-50%。

## 选择合适的 allocator

Rust 默认使用系统分配器（glibc/jemalloc）。对于嵌入式或体积敏感场景，可以切换到更轻量的分配器：

```toml
[profile.release]
# 在 Cargo.toml 中
[dependencies]
mimalloc = "*"
```

```rust
use mimalloc::MiMalloc;

#[global_allocator]
static GLOBAL: MiMalloc = MiMalloc;
```

结合以上配置，一个典型的 Rust 程序可以从十几 MB 缩减到 2-3 MB。
